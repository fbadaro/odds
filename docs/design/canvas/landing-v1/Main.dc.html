Quatro conectores, nove tags

A tag é contrato. A propriedade é documentação.

Oito tags de Context Map Pattern têm posição obrigatória — upstream, downstream ou os dois lados. A nona, [BBM], caracteriza o sistema em vez do contrato, e por isso é a única sem regra de posição.

Propriedades como team nunca alimentam uma regra. É o que deixa você preencher sem medo de ser julgado por isso.

Duas vistas

Elas não mostram a mesma coisa, e isso é de propósito.

Fluxo de relações

Como isto se integra?

Contextos como nós, relações como arestas, com o conector e as tags de padrão desenhados na linha. [BBM] aparece só aqui — risco de integração é pergunta desta vista.

Contenção aninhada

Como isto está organizado?

Domínio, subdomínios e contextos como caixas aninhadas — e o bloco external desenhado fora da fronteira do domínio, onde ele conceitualmente está.

100% no cliente

O seu mapa de contextos não é assunto de servidor nenhum.

Parse, validação e render acontecem no navegador. Compartilhar é uma URL com o desenho codificado dentro dela — não um link para um banco de dados alheio. Funciona offline, e o arquivo .odds é seu para colar num pull request.
