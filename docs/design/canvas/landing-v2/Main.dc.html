Como funciona

Três passos, e o terceiro é o que ninguém mais faz.

01

Escreva

Domínio, subdomínios core, supporting e generic, contextos, sistemas de terceiros e as relações entre eles. Um arquivo de texto que cabe num pull request.

02

Veja

O diagrama se redesenha a cada tecla, em duas vistas: o fluxo das integrações e a estrutura aninhada do domínio. Sem arrastar caixa nenhuma.

03

Ouça o que ele tem a dizer

Um Core Domain se conformando ao modelo de um sistema legado não é erro de sintaxe — é uma decisão cara. A ODDS aponta, explica por quê e sugere a saída.

O que ele pega

Nove linhas de texto, e um problema que ninguém tinha visto.

vendas.odds 9 linhas
domain Vendas {
  subdomain core Checkout {
    context Pagamento { team: "squad-pagamentos" }
  }
  external { context ERPLegado }
  mapping {
   Pagamento [CF] <-- [OHS] ERPLegado
  }
}
CONFORMIST_CORE L7:14

Risco estratégico: o contexto de Core Domain Pagamento está se conformando ao modelo de outro sistema. Considere um [ACL] para proteger a sua vantagem competitiva.

O arquivo está sintaticamente perfeito. O que a ODDS viu foi outra coisa: o pedaço do sistema onde mora a sua vantagem competitiva aceitou o modelo de um ERP legado sem camada de tradução no meio. Isso não quebra build nenhum — cobra depois, e caro.

É esse tipo de leitura que um quadro branco não faz.

Três severidades

Nenhuma delas apaga o seu diagrama.

O elemento com problema é desenhado visivelmente marcado e o resto continua de pé. Todo estado intermediário de um arquivo sendo digitado é erro de sintaxe — bloquear a tela seria piscar a cada tecla.

error o modelo se contradiz

O elemento sai do pipeline e não gera diagnóstico derivado — um engano seu nunca vira três mensagens.

SELF_RELATIONSHIP ROLE_CONFLICT
warning o desenho é arriscado

O arquivo é válido; a decisão de arquitetura é que cobra um preço — e a mensagem diz qual é.

CONFORMIST_CORE CORE_IN_SHARED_KERNEL
info higiene do mapa

Nada está errado. Falta dito: uma integração sem padrão declarado esconde o acoplamento real entre dois times.

UNDOCUMENTED_CONTRACT UNMAPPED_CONTEXT
A pergunta honesta

Por que não continuar no quadro branco?

Porque um quadro branco aceita qualquer coisa. Ele não sabe que [CF] e [ACL] no mesmo lado se contradizem, não percebe que você desenhou duas setas para o mesmo par de contextos, e envelhece no instante em que a reunião acaba.

Texto versiona. Texto entra em pull request. E texto pode ser lido por um validador.

Diff legível

Uma mudança de arquitetura aparece como três linhas alteradas, não como "alguém mexeu no board".

Uma relação, uma aresta

O par de contextos é a identidade da relação. Uma segunda linha para o mesmo par é apontada, não desenhada duas vezes.

Suprimir exige justificativa

Discordar de uma regra é legítimo — e fica escrito no arquivo, com o motivo, ao lado da linha.

Antes que você perca tempo

O que a ODDS não faz.

Design tático

Agregados, entidades e eventos dentro de um contexto ficam de fora. O recorte é estratégico, de propósito.

Edição arrastando caixa

O texto é a fonte única; o diagrama nunca escreve de volta. É o que mantém o seu arquivo previsível.

Julgar quem você é

Propriedades como team nunca alimentam uma regra. Nenhuma regra pressupõe que você controla o sistema que ela critica.
